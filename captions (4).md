### 3. Мережева взаємодія та архітектура клієнт-сервер

#### 3.1. Статичні vs Динамічні сайти
- **Статичний сайт:** Набір заздалегідь підготовлених HTML/CSS/JS файлів та картинок, які веб-сервер (Nginx, Apache) віддає клієнту «як є» без змін.
- **Динамічний сайт:** Веб-сторінка генерується сервером на льоту у відповідь на запит клієнта. Серверна програма (на C#, Node.js, Python, PHP) виконує SQL-запити до СУБД, обробляє параметри та динамічно формує HTML або JSON-відповідь.

#### 3.2. Мережевий стек: Модель OSI та стек TCP/IP
- Мережеві рівні забезпечують абстракцію передачі даних:
  - Фізичний та канальний (MAC-адреси, кабель/Wi-Fi).
  - Мережевий (IP-адресація, маршрутизація пакетів).
  - Транспортний (TCP — надійний потік з перевіркою доставки; UDP — швидкі дейтаграми без підтверджень, важливі для стримінгу та HTTP/3).
  - Прикладний (HTTP, HTTPS, DNS, FTP, WebSockets).

#### 3.3. Адресація та порти
- **IP-адреса:** Глобальна адреса комп'ютера в мережі.
- **Порти (0–65535):**
  - `0–1023` — системні (Well-Known): 80 (HTTP), 443 (HTTPS), 53 (DNS), 22 (SSH).
  - Клієнтський браузер для кожного з'єднання відкриває випадковий високий динамічний порт.
- **DNS (Domain Name System):**
  - Транслює імена (наприклад `kpi.ua`) в IP-адреси.
  - Робота локального файлу `hosts` (найвищий пріоритет співставлення до звернення до зовнішнього DNS-сервера).

### 4. Ідентифікація ресурсів: URI, URL, URN

- **URI (Uniform Resource Identifier):** Загальне поняття унікальної ідентифікації веб-ресурсу.
- **URN:** Ідентифікатор за іменем у просторі імен.
- **URL (Uniform Resource Locator):** Повна адреса із зазначенням схеми доступу.
- **Складові частини URL:**
  1. `Протокол` (`http://`, `https://`).
  2. `Логін/пароль` (застаріле, наприклад `user:pass@`).
  3. `Хост / Доменне ім'я` (або IP-адреса).
  4. `Порт` (якщо відрізняється від стандартного, наприклад `:8080`).
  5. `Шлях (Path)` до каталогу чи сценарію на сервері.
  6. `Параметри запиту (Query String)` через `?key1=val1&key2=val2`.
  7. `Фрагмент / Якір (Fragment)` через `#section`.

---

### 5. Протокол передачі гіпертексту (HTTP)

#### 5.1. Еволюція HTTP
- **HTTP/1.0 — HTTP/1.1:** Текстовий протокол, робота поверх TCP. У версії 1.1 додано постійні з'єднання (`Keep-Alive`), що дозволило завантажувати декілька ресурсів через одне TCP-з'єднання.
- **HTTP/2:** Бінарний протокол, мультиплексування запитів через один сокет, стиснення заголовків (HPACK).
- **HTTP/3:** Робота поверх нового транспортного протоколу **QUIC** (на базі UDP), що прискорює встановлення шифрованого з'єднання та усуває блокування черги (Head-of-Line Blocking).

#### 5.2. Заголовки HTTP та MIME-типи
- Клієнт і сервер обмінюються метаданими в заголовках: `Host`, `User-Agent`, `Accept`, `Content-Type`.
- **MIME-типи (Content-Type):** Повідомляють браузеру, як правильно обробляти тіло відповіді (`text/html`, `text/css`, `application/javascript`, `application/json`, `image/png`).

#### 5.3. Ключові методи HTTP: GET vs POST
- **GET:**
  - Призначений для запиту та отримання даних без зміни стану сервера.
  - Параметри запиту передаються прямо в URL (Query String).
  - Кешується браузерами та проксі-серверами.
  - Має обмеження на довжину адресного рядка, не підходить для передачі паролів або бінарних файлів.
- **POST:**
  - Призначений для відправки даних на сервер (реєстрація, збереження замовлення, оновлення бази).
  - Дані передаються у **тілі (body)** запиту.
  - Не кешується автоматично браузером.
  - Дозволяє передавати великі обсяги даних будь-якого формату (JSON, мультиформ, файли).

#### 5.4. Коди відповідей сервера
- `200 OK` — запит успішно оброблено.
- `301 / 302` — перенаправлення на іншу адресу.
- `400 Bad Request` — помилка у синтаксисі запиту клієнта.
- `404 Not Found` — запитаний ресурс відсутній на сервері.
- `500 Internal Server Error` — неперехоплена помилка серверного скрипту.
